# dogurdf 轮足机器人参数说明

本文整理 `urdf/dogurdf.urdf` 里的全部参数，说明每个数字的含义、它决定了什么，以及在转成训练用 MJCF 时哪些被沿用、哪些被改掉。

文中所有数值都从 URDF / CSV / 编译后的模型里读出并交叉核对过，不是估算。单位统一为 **米 / 千克 / 弧度 / 牛·米**。

---

## 1. 这是一台什么机器人

四条腿，每条腿 4 个关节，共 **16 个自由度**：

```
base_link (机身)
 └── ?_hip_link      绕 x 轴  ——  侧摆（roll 方向张开/收拢腿）
      └── ?_thigh_link   绕 y 轴  ——  大腿俯仰
           └── ?_calf_link    绕 y 轴  ——  小腿俯仰
                └── ?_wheel_link   绕 y 轴  ——  轮子（连续旋转，无限位）
```

`?` 是 `FL`/`FR`/`RL`/`RR`（前左、前右、后左、后右）。

前三个关节是**位置控制**的腿关节，第四个是**速度控制**的驱动轮。所以它不是纯足式四足，而是"腿 + 轮"混合平台：腿负责姿态和悬挂，轮负责推进。

### 一个关键的运动学限制

四个轮子的转轴都固定在机体 **y 方向**（`axis = 0 1 0`）。hip 关节绕 x 轴转，只会让轮平面侧倾，**不会改变轮子的滚动方向**。

这意味着它是**差速转向平台**（像坦克/扫地机）：

- 前进后退 → 四轮同向转
- 原地转向 / 转弯 → 左右两侧轮子差速
- **横向平移做不到** —— 没有任何关节能让轮子朝侧向滚

所以训练配置里 `lin_vel_y` 指令被锁死为 0（[dogurdf_config.py](../../../src/cfg/dogurdf_config.py)），否则就是在让策略追一个物理上不可达的目标。

## 2. 质量与惯量

### 各连杆质量

| 连杆 | 质量 (kg) | 数量 | 小计 (kg) |
|---|---|---|---|
| `base_link` 机身 | 1.970 | 1 | 1.970 |
| `?_hip_link` 侧摆件 | 0.297 | 4 | 1.189 |
| `?_thigh_link` 大腿 | 1.707 | 4 | 6.830 |
| `?_calf_link` 小腿 | 0.480 | 4 | 1.919 |
| `?_wheel_link` 轮 | 0.581 | 4 | 2.324 |
| **整机** | | | **14.23** |

注意质量分布很反直觉：**机身只占整机 14%（1.97 kg），四条大腿加起来 6.83 kg，是机身的 3.5 倍**。这台机器人的质量绝大部分在腿上。

这有两个后果：

1. 摆腿会显著改变整机质心和转动惯量，机身姿态对腿部动作很敏感。
2. 力矩需求主要来自"举起腿自身"，而不是"驮起机身"。

### 惯量张量

URDF 里每个连杆有 6 个惯量分量（`ixx iyy izz` 主对角 + `ixy ixz iyz` 交叉项），定义在连杆质心处。例如大腿：

```xml
<inertia ixx="0.0228508" ixy="-6.82e-05" ixz="-0.001805"
         iyy="0.0175783" iyz="5.8e-06"   izz="0.0091144"/>
```

`ixx` 大、`izz` 小说明大腿是细长杆状（绕自身长轴转动惯量最小）。

> **一处数据不一致，值得知道**：`urdf/dogurdf.csv` 是 SolidWorks 导出的属性表，里面也有一套惯量。两者**质量完全一致**，但惯量对不上：
>
> | 连杆 | 惯量迹 (CSV) | 惯量迹 (URDF) | 比值 |
> |---|---|---|---|
> | base_link | 0.0107 | 0.2698 | **25.2×** |
> | thigh | 0.0210 | 0.0495 | 2.4× |
> | hip | 0.0015 | 0.0019 | 1.25× |
> | calf | 0.0199 | 0.0199 | 1.00 |
> | wheel | 0.0098 | 0.0098 | 1.00 |
>
> CSV 的值是绕**质心**的纯连杆惯量；URDF 里 base_link 和 thigh 的值明显被人为放大过（机身差 25 倍不可能是坐标系差异）。**实际仿真用的是 URDF 的值**，MJCF 也沿用它。如果发现机身转动比预期迟钝，这就是原因；要改的话对照 CSV 那一列。

## 3. 几何尺寸

### 关节安装位置（相对父连杆）

| 关节 | 偏移 xyz | 安装角 rpy | 含义 |
|---|---|---|---|
| `hip` | `(±0.3265, ±0.08, 0)` | `(0,0,0)` | 机身四角，x 前后 / y 左右 |
| `thigh` | `(0, ±0.1308, 0)` | `(0, **1.0197**, 0)` | 向外侧伸 13 cm，**大腿预倾 58.4°** |
| `calf` | `(0, 0, -0.34)` | `(0, **-1.0861**, 0)` | 沿大腿向下 34 cm，**小腿反折 -62.2°** |
| `wheel` | `(-0.10583, ±0.045, -0.32311)` | `(0, **-0.21627**, 0)` | 小腿末端，**轮偏转 -12.4°** |

`rpy` 里那些 `±3.1416` 是 SolidWorks 导出的坐标系翻转（π 绕 x、π 绕 z），净效果就是上表的俯仰角；左右腿的符号差异只是镜像。

### 由此得出的整机尺寸

| 量 | 数值 | 怎么来的 |
|---|---|---|
| 大腿长 | 0.340 m | thigh→calf 的 z 偏移 |
| 小腿长（等效） | 0.340 m | calf→wheel 在 xz 平面的距离 |
| **轮距（前后轴距）** | **0.653 m** | hip 的 x 偏移 ±0.3265 |
| **轮距（左右轮距）** | **0.512 m** | 实测轮心 y = ±0.2558 |
| **轮半径** | **0.113 m** | 轮碰撞体 cylinder radius |
| 机身碰撞盒 | 0.474 × 0.25 × 0.12 m | base_link 的 box |

大腿和小腿等长（都是 0.34 m），是标准的对称两连杆构型。

### 站立高度

标定出的名义站姿是 **`thigh=0.20, calf=-0.70`**，此时：

- 轮心正好落在 hip 轴正下方（x 偏差仅 0.0001 m）—— 受力最合理，无额外侧向力矩
- **机身高度 0.347 m**，机身底面离地 0.287 m

在关节限位内、且轮子仍是最低接触点、且轮心大致在 hip 下方（±8 cm）的姿态里，机身高度可在 **0.223 ~ 0.636 m** 之间调节。这就是这台机器人的"可蹲可站"范围。

## 4. 关节限位与电机参数

### URDF 声明值

| 关节 | 下限 | 上限 | 范围 | effort | velocity |
|---|---|---|---|---|---|
| `hip` 侧摆 | -0.6 | +0.6 | ±34.4° | 300 | 14 |
| `thigh` 大腿 | -0.7 | +1.75 | 140° | 300 | 14 |
| `calf` 小腿 | -1.0 | +0.35 | 77.4° | 300 | 14 |
| `wheel` 轮 | — | — | 无限位（`continuous`） | — | — |

hip 的活动范围最小（±34°），符合它只做侧向姿态微调的角色。

### effort=300 是占位值，不能用

URDF 里四个关节的 `effort` 全是 `300`、`velocity` 全是 `14` —— 这是 SolidWorks 导出器的默认填充，不是真实电机规格（同尺寸的 XG 四足腿部电机只有 28 N·m）。直接用会让策略学出依赖超大力矩的暴力动作，完全无法迁移到实物。

**训练实际采用的值**（按实物电机规格）：

| | 力矩限幅 | 速度限幅 |
|---|---|---|
| 腿关节（hip / thigh / calf） | **150 N·m** | 14 rad/s |
| 轮电机 | **53 N·m** | **12.5 rad/s** |

轮速上限直接决定车速上限：

```
最高车速 = 12.5 rad/s × 0.113 m = 1.41 m/s
```

训练指令范围取 `vx ∈ [-1.0, 1.0] m/s`，占满速的 71%，留出控制余量。

### 实测的力矩余量

| 工况 | 腿部峰值力矩 | 轮峰值力矩 |
|---|---|---|
| 保持站姿 3 s | 13.0 / 150 (9%) | 1.3 / 53 (2%) |
| 行驶 1.0 m/s | 27.5 / 150 (18%) | 35.4 / 53 (67%) |
| 行驶 1.41 m/s 满速 | 32.4 / 150 (22%) | 53 打满 |

腿部余量充裕；轮子在接近满速时会打满限幅，这符合"电机额定转速处扭矩下降"的物理现实。

## 5. 碰撞体

URDF 已经把 mesh 简化成了 primitive（这点做得很好，直接可用于仿真）。以 FL 腿为例：

| 连杆 | 形状 | 尺寸 | 位置 |
|---|---|---|---|
| `base_link` | box | 0.474 × 0.25 × 0.12 | 中心 |
| `hip` | cylinder | r=0.0615, len=0.06 | 侧向 |
| `thigh` | cylinder | r=0.07, len=0.145 | 关节处 |
| `thigh` | box | 0.064 × 0.045 × 0.3 | 大腿杆 |
| `calf` | cylinder | r=0.016, len=0.15 | 小腿上段 |
| `calf` | cylinder | r=0.015, len=0.13 | 小腿下段（斜 0.45 rad） |
| `calf` | cylinder | r=0.065, len=0.045 | **轮毂盘** |
| `wheel` | cylinder | **r=0.113**, len=0.04 | 轮 |

### 轮毂与轮子几乎同心（重要）

轮毂盘（r=0.065）和轮子（r=0.113）的圆心 z 分别是 0.1139 和 0.1130 —— 几乎重合。所以轮子在任何朝向都比轮毂多伸出约 **4.8 cm**。

实测扫过整个关节可达范围（机身 0.14~0.41 m）、加上最多 46° 机身俯仰，轮毂离地余量始终稳定在 **4.85~5.12 cm**。这是结构性的，不是某个姿态的巧合：只要轮子接地，轮毂就不可能碰地。

## 6. URDF → 训练 MJCF 的改动

同目录下有三个文件，是一条流水线：

```
urdf/dogurdf.urdf          原始导出（SolidWorks）
  ↓ mujoco 自动转换
dogurdf_from_urdf.xml      自动产物：仅 16 关节，无机身 body / 无浮动基座 / 无执行器 / 无地面
  ↓ 手工补齐
dogurdf.xml                训练实际使用 ← 只有这个被代码引用
```

`dogurdf.xml` 相对 URDF 的改动，以及为什么：

| 项目 | URDF | 训练 MJCF | 原因 |
|---|---|---|---|
| 基座 | 固定（无浮动自由度） | `torso` body + `<freejoint/>` | URDF 没有浮动基座概念，不加则机器人无法移动 |
| 自由度 | 16 | 23 / 22（qpos/qvel，含基座 7/6） | 同上 |
| 执行器 | 无 | 16 个 `<motor>` | URDF 不描述执行器 |
| 力矩限幅 | 300（占位） | 腿 150 / 轮 53 | 见 §4 |
| 地面 | 无 | plane + 棋盘材质 | 训练需要地面 |
| 碰撞掩码 | 默认全开 | 机体 `contype=0 conaffinity=1`，地面 `contype=1 conaffinity=0` | **见下** |
| 关节阻尼 | 未指定 | `damping=0.5 armature=0.01` | 抑制高频振荡 |
| 名义姿态 | 无 | `<keyframe>` 记录 thigh=0.20 calf=-0.70 | 便于复位与可视化 |

### 为什么必须改碰撞掩码

MuJoCo 的 GPU 后端 MJX（版本 3.4.0）**不支持 box↔cylinder 碰撞**（我逐对测过 sphere/capsule/box/cylinder 全部组合，只有这一对抛 `NotImplementedError`）。而本机器人的轮子/小腿是 cylinder、大腿/机身是 box，按 URDF 默认掩码会生成这类自碰撞对，`mjx.put_model` 直接报错。

解法是让机体所有几何体只与地面碰撞，互相不碰：机体 geom 全设 `contype=0 conaffinity=1`，地面设 `contype=1 conaffinity=0`。代价是**关闭了机体自碰撞**（腿与腿、腿与机身可以互相穿透），对平地行驶任务可以接受。

### 视觉 mesh 的处理

`meshes/` 只有 5 个 STL（base + FL 的四个连杆）。其余三条腿在 URDF 里靠负 scale 镜像复用 FL 的 mesh，MJCF 也照此做（`scale="1 -1 1"` 等）。

这些 mesh **纯视觉**，全部 `contype=0 conaffinity=0 density="0"`：不参与碰撞、不贡献惯量（惯量全部来自显式 `<inertial>`）。实测代价：编译多约 1 秒，256 env 步进慢 3%（噪声量级），设备端多约 13 MB。所以保留它们不影响训练性能，换来的是可视化时能看清真实外形。

## 7. 训练配置速查

对应 [src/cfg/dogurdf_config.py](../../../src/cfg/dogurdf_config.py)：

| 项 | 值 | 备注 |
|---|---|---|
| 动作维度 | 16 | 前 12 腿位置偏移，后 4 轮速 |
| 观测 actor / critic | 56 / 80 | 轮子只进速度不进位置 |
| 腿 PD 增益 | Kp=150, Kd=4 | 实测站姿下沉 2 cm |
| 轮速度环 | Kp=0, Kd=2.0 | 实测跟踪误差 0.01 rad/s |
| 动作缩放 | 腿 0.25 rad, 轮 12.5 rad/s | |
| 控制周期 | 0.02 s | dt=0.005 × decimation 4 |
| 名义机身高度 | 0.347 m | |
| 指令范围 | vx ±1.0 m/s, wz ±1.0 rad/s, **vy ≡ 0** | vy 物理不可达 |

**为什么轮子只进速度不进位置**：`continuous` 关节的 qpos 是无界累加量，转 10 圈就是 62.8 rad，会撑爆观测的 `clip(-100, 100)`，且轮子转过的绝对角度对控制毫无信息量。

**统一力矩律**：`tau = Kp·(q_目标 - q) + Kd·(ω_目标 - ω)`。轮子 `Kp=0` 让位置项自动消失，腿关节 `ω_目标=0` 退化成纯阻尼项 —— 一条公式覆盖两类关节，物理循环里不需要写分支。

## 8. 关节顺序（容易踩坑）

同一批关节有两套排列，二者**不是恒等映射**：

**MJX 顺序**（模型编译后的物理顺序，按腿分组）：
```
FL_hip FL_thigh FL_calf FL_wheel | FR_... | RL_... | RR_...
索引    0        1        2        3        4-7      8-11    12-15
```

**策略顺序**（神经网络看到的顺序，按关节类型分组）：
```
12 个腿关节（FL,FR,RL,RR 各 hip/thigh/calf） | 4 个轮关节
索引 0-11                                      12-15
```

两者的置换关系（定义在 [src/robots/dogurdf.py](../../../src/robots/dogurdf.py)，已用编译模型验证过）：

```python
mjx_to_policy_idx = (0,1,2, 4,5,6, 8,9,10, 12,13,14,  3,7,11,15)
policy_to_mjx_idx = (0,1,2,12, 3,4,5,13, 6,7,8,14, 9,10,11,15)
```

之所以要分组，是因为策略需要"腿动作"和"轮动作"在向量里各占连续一段，才能分别施加位置控制和速度控制。改动涉及关节索引的代码时，务必确认手上的数组是哪套顺序 —— 之前的 XG 机器人两套顺序恰好相同，所有 reindex 代码路径都没被真正检验过。
