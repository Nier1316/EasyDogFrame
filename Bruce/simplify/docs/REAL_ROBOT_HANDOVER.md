## 2. 安全铁律（不可违反）

1. **人在现场、随时能断电**。真机测试会施加力矩。
2. **需要吊起的测试（T1/T3/T4/T5）必须先确认腿和轮全部离地**，再开始。
3. **`Ctrl+C` 是软急停**（装了 `SIGINT` 处理器的示例），但**它不等于断电**。
4. ⚠️ **16 个示例会发使能帧但没有软急停**：Ex18/19/20/21/22/23/29/32/41/44/45/46/47/48/49/57。
   本清单**不涉及**这些示例；不要顺手去跑它们。
5. **任何"改数值"的动作（T0 的 `tau_ff`）必须：改一处 → 只跑一次验证 → 立刻判断好坏 → 不好立即改回**。
   不要连续改多个关节/多个参数。
6. 录制数据集时注意磁盘：**约 420 KB/s**（10 分钟 ≈ 250 MB）。开始前确认剩余空间。
7. T0/T2/T6/T7 是**在站立状态下**做的（狗在地上）。做这些时**其他三条腿必须保持已知良好设置**，
   一次只动一条腿的候选参数，避免整机失去支撑。

## 3. 执行顺序（严格按此顺序）

> 顺序理由：T0/T1/T2 是**地基**（信号与自重标定不准，后面所有数据都会被污染）；
> T3~T5 便宜且结论直接；T6~T8 依赖前面已就绪的记录链路。

### T0 —— 破 `thigh tau_ff` 符号悬案（最高优先级）

- **背景**：`include/motor/motor_calibration.h` 的 `JOINT_IMPEDANCE[..][1].tau_ff` 代码是
  **`+5.0f`**，但行内注释与 commit `6546688` 的提交信息都写 **`−5`**。一直未定论。
  `tau_ff` 是**重力前馈**，符号错会直接表现为 **"抬腿无力 / 整体下塌"**。
- **前置**：狗正常站立在地面（可有人扶）。当前表值：`hip = −10`、`thigh = +5`、`calf = +12`（以文件为准）。
- **步骤**：
  1. 在 `main.cpp` 启用 `Example53_MeasureGravityFF`；构建；运行。
  2. 它会：RL 站立 → 热身 → 记录稳态 `cal_torque` → **打印"重力前馈建议"** →
     **新增打印"表内值 / 实测建议 / 差值 / 判定"对比表** → 自动趴下。
- **期望输出**（关键片段）：
  ```
  === 与表内当前值对比（差异大 → 优先改表；符号相反 → 表内符号很可能错了）===
  关节          表内值       实测建议       差值   判定
  thigh         +5.0         <实测>       <差>   <判定>
  ```
- **判据**：
  - 若打印 `⚠ 符号相反 → 表内符号很可能错`：**该结论就是本次要交付的答案**（先不要自己改，把结论上报）。
  - 若判 `一致，保持` 或 `可微调`：说明 `+5` 正确，符号悬案可关闭。
- **异常处理**：若站立过程跌倒/触发跌倒检测，**不要重试超过 2 次**；记录现象（哪条腿、怎么塌）并上报。
- **耗时**：约 2 分钟/次。

### T1 —— 力矩通道校验（Ex58）

- **前置**：**狗吊起，腿与轮全部离地**。运行时会提示是否测试轮子：**默认选 N（仅 12 个腿关节）**，
  除非你能按住轮子或让轮子抵住地面。
- **步骤**：启用 `Example58_TorqueChannelCheck` → 构建 → 运行 → 按提示回车 → 逐电机自动扫。
  施加力矩时**用手轻扶被测量的那条腿**（减少摆动，不要用力顶）。
- **期望输出**：一张 `电机 / 量程 / 零偏 / +T1 / +T2 / −T1 / −T2 / 最大σ / 判定` 表；
  结束时打印 `测试电机 12 个，通过 N 个`，并给出 `log/sysid/torque_check_*.csv` 路径。
- **判据**：`|τ_回读 − τ_指令| ≤ max(0.5, 25%·|τ_指令|)` 且符号一致且 `|零偏| < 0.5 N·m`。
  **有任何 WARN 都要上报**（通道不可信时后面所有 τ 数据都不能用）。
- **耗时**：约 10~20 分钟。

### T2 —— 重力矩系数与质量-质心（Ex59）

- **前置**：
  1. **先用台秤称重并记下**：机身（不含腿，含电池）、单条大腿组件、单条小腿+轮组件；
  2. **狗吊起**；**机身垫平**（示例会尝试开 IMU 检查倾角，>10° 会警告）；
  3. 若能拿到 `Example47` 测过的 `J`，记下来（没有就填 0，示例会跳过 `I_c`）。
- **步骤**：启用 `Example59_GravityMassIdentify` → 构建 → 运行 →
  按提示输入称重值（**留空用默认、填 0 跳过**）→ 之后 12 个关节自动逐个双向慢扫。
- **期望输出**：每个关节一行 `a / b / c / G=m·g·d / φ / 残差RMS / 备注`；
  末尾给出 `G_j = m·g·d` 汇总表 + **建议写入 `LINK_DYNAMICS`/`BODY_MASS` 的数值** +
  `log/sysid/gravity_summary_*.csv`。
- **判据（自查，用来判断数据是否可信）**：
  - **四条腿同一关节的 `G_j` 应接近**；明显偏离的那条腿 → 优先怀疑该腿力矩通道或机械卡滞（记进报告）。
  - `残差RMS` 应明显小于 `G`（例如 < 20%）；`备注` 出现 `⚠位置几乎不动` → 该关节数据不可用。
  - `G` 的量级应为**几到二十 N·m**；出现 0 或几十以上 → 异常。
- **耗时**：约 2.5 分钟扫描 + 输入。

## 4. 约定速查（写错这些，数据就废了）

| 项 | 约定 |
|---|---|
| CAN 口 | `0=FL, 1=FR, 2=RL, 3=RR`（前/后 × 左/右） |
| 电机号 | `1=hip, 2=thigh, 3=calf, 4=wheel` |
| 数据集索引 | **CAN 顺序**：`i = can*4 + (motor_id-1)` → `00=FL-hip … 03=FL-wheel, 15=RR-wheel`（**不是** POLICY 顺序） |
| 角度坐标 | `GetStatus().position` = `SendImpedance` 接受的位置 = `leg_fk`/`leg_jacobian` 的输入，**同一坐标**；不要再做标定换算 |
| 力矩量程 | hip 120 / thigh 120 / calf 200 / wheel 52 N·m |
| 参照量级 | 腿库仑摩擦 **1.6~6.2 N·m**；重力矩 **8~20 N·m**；端到端延迟 **≈24 ms**（历史 18~30） |
| 轮速环参数 | 真机 `WHEEL_KVP=3.0`、`WHEEL_KVI=0.05`（固件速度环，内环 50 µs） |
| ⚠ 轮子 kd | `sim2sim.py` 用 **2.0**，`rl_controller.h` 用 **1.0** —— 两者不一致，属于已知结构性差异，**不是你的 bug**，照实上报即可 |
| 控制频率 | 策略 50 Hz；电机收发 500 Hz；IMU 100 Hz |
| 数据集聚类 | `log/dataset_<ts>.csv` + `.meta.txt`；188 列；`wall_ms` 可与 sim2sim `--record` 直接对齐 |

`c_*` 列的含义随 `c_mode_i` 变化（离线分析必须按 mode 解释）：
- `0=IMPEDANCE`：`c_pos`=目标位置, `c_vel`=目标速度, `c_kp`=kp, `c_kd`=kd, `c_tau`=τ_ff
- `1=SPEED`：`c_pos`=0, `c_vel`=目标速度, `c_kp`=kvp, `c_kd`=0, `c_tau`=ki
- `2=POSITION`：`c_pos`=目标位置, `c_vel`=0, `c_kp`=kvp, `c_kd`=kp, `c_tau`=kvi

## 5. 已知坑（会浪费你时间的东西）

1. **每个示例之间必须重新构建**（改 `main.cpp` 后不 `make` 等于没改）。
2. **不要同时启用两个示例** —— 会争抢 CAN 与电机所有权。
3. **T1/T3/T4/T5 忘记吊起** → 力矩/位置会顶到地面，结果全废且有危险。
4. **`MOTOR_OR_Vbus (0x07)` 是本工程首次启用**（Ex24 的参数表里从来没有它）。
   若数据集里 `m_vbus_*` 全为 0，**属正常**，在报告里注明即可，不影响其它数据。
5. **温度列开头几秒为 0** 属正常（1 Hz 轮询，第一次要等 1 s）。
6. **数据集在前 1 秒可能不满行**（写线程 1 s flush 一次；程序正常退出会 drain，异常 kill 会丢最多 1 s）。
7. **`dropped > 0`** 出现在结束打印里 → 说明磁盘/缓冲跟不上，**缩短单次录制时长**再重录。
8. **`Example53` 会自己趴下**，不是故障。
9. 别用 `sudo` 改权限；`/dev/ttyACM0` 打不开通常是 USB 没插好或被别的进程占用（检查是否有上次没退干净的 `can_motor_app`）。
10. **不要 `git commit` / `git push`**；也不要改 `weights/`、`policy_weights.h`、仿真侧文件。

## 6. 出问题时的处理与上报

| 现象 | 处理 |
|---|---|
| 电机发出一声异响/抖动剧烈 | **立刻 Ctrl+C**，然后断电；记录是哪个 CAN/电机、当时的模式与命令 |
| 狗站立时明显下塌/侧倾 | 停止测试，记录（这本身就是 T0 的重要证据） |
| 位置越限自动中止（打印 `位置越限`） | 正常保护，记录该电机与当时的激励幅值 |
| 轮子超速触发急停 | 记录段作废，重跑时不要按住轮子、也不要改程序里的幅值 |
| `MotorManager 初始化失败` | 检查 USB、设备路径、上一个进程是否退出 |
| 数据体检不过（丢帧多/命令不活跃） | 重录；连续 2 次不过就上报，不要反复试 |

## 8. 不要做的事（反模式）

- ❌ 不吊起就跑 T1/T3/T4/T5。
- ❌ 为了让数据"好看"而调大激励幅值（尤其轮子，会触发急停）。
- ❌ 只跑一遍就下结论（延迟/伺服至少 2 段以上，n≥2）。
- ❌ 把 `c_*` 与 `m_*` 当成 POLICY 顺序去对齐（那是 CAN 顺序）。
- ❌ 用 τ 反馈做任何估计**而不先看 T1 的结论**。
- ❌ 改 `tau_ff`/`LINK_DYNAMICS`/权重后不重跑验证。
- ❌ 把"没测到"写成"测到是 0"（例如 Vbus 全 0 要写"未读到"）。
