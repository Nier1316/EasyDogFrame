# Action Delay 辨识报告（真机实测）

> 日期：2026-08-25
> 对象：dogurdf 轮足策略 sim2real 部署
> 方法：真机正弦扫频 + 基波相位拟合（Example38）
> 结论速览：**真机纯传输延迟 ≈ 18~30ms（均值 24ms）→ 训练侧 `action_delay_steps = 1`（20ms），建议叠加 0~2 步随机化**

---

## 1. 背景与目的

RL 策略在真机部署时，动作从「策略输出」到「执行器响应」之间存在延迟。训练环境若不模拟该延迟，策略对执行延迟不鲁棒，sim2real 会打折扣。

**目标**：实测真机纯传输延迟 `T_delay`，换算成 50Hz 控制周期下的动作延迟步数 `action_delay_steps`，作为训练侧超参。

**关键区分**（本报告贯穿始终）：
- **纯传输延迟**（action_delay 应覆盖的）：信号链路（CANET TCP + 固件）+ 采样对齐，量级约 20ms。
- **闭环响应滞后**（仿真中同样存在，不需补偿）：执行器 + 身体动力学的相位滞后，量级可达数百 ms，**不是** sim2real 差距。

---

## 2. 测量方法

### 2.1 原理：频域相位法

给执行器发正弦命令 `A·sin(2πft)`，用最小二乘提取反馈基波的幅度与相位，相位差 `φ(f)` 即响应滞后。纯传输延迟在频域表现为**线性相位**：

```
φ(f) = 2π·f·T_delay   （滞后为正）
```

若测得的等效延迟 `T = φ/(2πf)` 随频率恒定 → 纯延迟；若随频率下降 → 叠加了闭环惯性。

### 2.2 双通道设计（Example38）

| 通道 | 激励 | 反馈 | 性质 |
|---|---|---|---|
| **阶段A 腿** | calf 位置正弦 `q0+0.03·sin(2πft)`，PD `kp=250/kd=40` | 实际位置 | 位置**闭环**，滞后含 PD+机械惯性 → 只是**上界** |
| **阶段B 轮**（主判据） | 轮扭矩正弦 `±1.0 Nm`，悬空 | 轮速 | **开环**积分环节，恒有 −90° 相移，扣除后余量 = **纯传输延迟** |

### 2.3 关键实现点

1. **符号约定**：fit 以 `sin` 为相位基准，反馈滞后 δ 时测得 `phase_f = 90° + ωδ`（**正** dphi）。初版实现符号取反导致全负、0 有效点，已修正：
   - 腿：`T = φ/(2πf)`
   - 轮：`T = (φ − 90°)/(2πf)`（φ>90° 才有效）
2. **实际时钟**：命令与反馈共用 `steady_clock` 真实时间轴采样，避免 `usleep(20ms)+16次Send+16次Get` 的循环抖动引入相位误差。
3. **过渡段剔除**：每频率丢前 0.5 周期再拟合。
4. **频率选择**：腿 0.5/1/2/3 Hz；轮 2/4/6 Hz（低频扭矩→速度幅值过大，且摩擦死区污染严重，2Hz 数据仅参考）。

## 3. 测量数据（修正后）

### 3.1 阶段B 轮通道（主判据）

| 轮 | 2 Hz | 4 Hz | 6 Hz |
|---|---|---|---|
| 轮0(FL) | 无效(<90°) | 超速跳过 | **21.8 ms** |
| 轮1(FR) | 2.5 ms* | **18.1 ms** | **26.9 ms** |
| 轮2(RL) | 无效(<90°) | 无效(<90°) | 无效(<90°) |
| 轮3(RR) | 4.7 ms* | 超速跳过 | **29.7 ms** |

\* 2Hz 为摩擦死区假象，剔除。

**可信段（4~6Hz）：18.1 / 21.8 / 26.9 / 29.7 ms，均值 ≈ 24 ms。**

轮2 全无效：其摩擦最大（`WHEEL_FF` 实测 CAN2 阻力 0.8 Nm 为四轮之最），1.0 Nm 幅度过不去死区，波形严重失真。

### 3.2 阶段A 腿通道（上界参考）

| 频率 | 滞后范围 | 等效 T（上界） |
|---|---|---|
| 0.5 Hz | 43°~68° | 238~378 ms |
| 1.0 Hz | 71°~74° | 196~207 ms |
| 2.0 Hz | 93°~106° | 130~147 ms |
| 3.0 Hz | 108°~120° | 100~111 ms |

16 点均值 185 ms。**该值不是纯延迟**（详见 §5），仅作上限。

## 4. 结论

```
真机纯传输延迟 ≈ 24 ms（可信区间 18~30 ms）
action_delay_steps = round(24 / 20) = 1
```

**建议训练配置：`action_delay_steps = 1 ± 随机(0~2步)`**，每 episode 从 0~3 步采样，让策略对延迟鲁棒、不赌单点。取 2 步（40ms）会白白牺牲 16ms 响应性，不必要。

---

## 5. 腿为什么有「百余毫秒延迟」

**那不是延迟，是闭环相位滞后等效成的时间**，判断依据：

1. **幅值暴跌**：0.5Hz 时反馈幅值仅为命令的 42%（0.013/0.03）。纯延迟不衰减幅值。
2. **等效 T 随频率递减**（378→100ms）：二阶系统相位特征，非纯延迟的恒定 T。
3. **0.5Hz 滞后 68°**：若为纯延迟需 δ≈378ms，但同链路轮通道仅测到 ~24ms，物理不可能。

**根因 = 支撑腿等效惯量大 + PD 力预算不足**：

```
J_eff ≈ 8 kg·m²   （狗体质量经腿几何映射到 calf 轴）
ωn = √(kp/J_eff) = √(250/8) ≈ 0.9 Hz   ← 闭环固有频率仅 ~1Hz
PD 峰值扭矩 = 250 × 0.03 = 7.5 Nm，接近每腿承重保持力矩（4~7.5 Nm）
```

闭环带宽 ~1Hz，1~3Hz 正弦命令自然滞后 70~110°；且 PD 在准静平衡边缘没有多余力跟随正弦，所以 0.5Hz 幅值就掉一半。

**关键洞察**：该滞后是**物理动力学**（真机狗质量 × 腿长 × PD），MuJoCo 仿真中狗体质量、腿长、PD 相同，**仿真里同样存在**。因此它不是 sim2real 差距，**不应**算进 action_delay——action_delay 只补偿仿真缺失的传输/链路延迟（~24ms）。腿的上界数据反而印证了 1 步结论的正确性。

## 6. 落地建议

| 层面 | 动作 |
|---|---|
| **训练环境** | 配置 `action_delay_steps=1`，实现为动作延迟缓冲（当前步应用 N 步前的 action，`last_action` 跟随延迟后的动作） |
| **sim2sim.py 评估** | `control_step` 加同样的延迟缓冲，保证评估与训练一致（本仓库可改） |
| **真机侧** | 保持链路低延迟（发送队列不阻塞、GetStatus 数据龄小）；**不要**人为加延迟 |
| **后续优化** | 若想提升腿跟随带宽，可评估提高 `LEG_KP`（需重新 sim2real 验证，当前 250 已实测稳定） |

## 7. 复现指引

运行 `Example38_ActionDelayMeasure`（当前 main.cpp 已启用）：

```
前置条件：狗架起，四腿支撑承重、轮子悬空（同 Example35 条件）
流程：起立到 DEFAULT_POSE(10s) → 腿扫频 → 轮扫频 → 汇总
安全：全程 Ctrl+C 急停；轮速超 8 rad/s 自动跳过保护
```

**参数可调**（`src/example.cpp` Example38）：
- 轮幅 `W_AMP`：摩擦大的轮子(如 CAN2)无效时可降到 0.8；若仍无效可升到 1.5（但 2Hz 会超速跳过）。
- 频率序列：轮 4~6Hz 段最可信，2Hz 数据剔除。

**可验证项**：在 `sim2sim.py` 对支撑腿做同样扫频，若仿真腿滞后接近真机（70~110°），则实锤「腿滞后 = 物理动力学」，`action_delay_steps=1` 结论稳固；若仿真明显更小，则真机腿存在额外问题（电机扭矩不足 / 传动间隙）需深挖。
