## 1. 前置条件（**缺一不可**，PACE §2.1）

| # | 条件 | 为什么 | 怎么确认 |
|---|---|---|---|
| 1 | **狗刚性固定**（夹具夹紧机身） | PACE 前提是 "fixed base, no base motion"；**吊带会摆动**，摆动的基座会引入未建模力旋量，辨识结果不可信 | 用手推机身，应几乎不动 |
| 2 | **全部离地、无任何接触**（含腿间） | 站立时基座惯量比腿/驱动大 1~2 个数量级，只有空中数据能隔离"腿+驱动"动力学 | 目视 + 手动确认 |
| 3 | **机身尽量水平** | 重力方向参与动力学；倾斜会让各关节的等效重力偏置不同 | 垫平；可用 `Example33` 看 IMU |
| 4 | **固件补偿开关冻结** | 论文实测：补偿可引入与真实 armature 同量级的**表观惯量**（Tytan `8.1e-3 kg·m²`）⇒ 辨识与部署必须用同一套补偿配置 | 记录当前 cogging/摩擦补偿的设置，**后续部署不得更改** |
| 5 | **kp/kd 与部署完全一致，且偏低** | 论文明确：故意用低增益让闭环极点落在可激励带宽内；且**禁止把 PD 增益与动力学联合优化**（Eq.7 存在非唯一最优） | 本流程默认 `kp=50 / kd=1`（与 Go2W 实物部署同量级） |
| 6 | 轮子不参与 | PACE 无轮式平台；轮关节无重力负载，`q̃b/τf` 语义不成立 | 本示例只动 12 个腿关节，轮子保持 0 速 |

**记录到 meta**：夹具方式、机身姿态、固件补偿设置、电池电压、环境温度、狗的质量/是否带负载。

## 2. 参数选择（示例里可直接改）

| 参数 | 示例默认 | PACE 依据 | 调整建议 |
|---|---|---|---|
| 时长 | **20 s** | 20~60 s | 若关节发热/夹具发烫，可降到 15 s（≥20 s 更稳） |
| 频段 | **0.1 → 10 Hz** | 官方例程上限 10 Hz；理想是 `f_policy/2`，受结构限制时可降 | **先看腿的实际跟随**：若高频段明显跟不上/抖动，把上限降到 5 Hz（论文 ANYmal 只用到 2 Hz 仍然成功） |
| 幅值 | **0.06 rad** | 官方未给幅值 | ⚠️ **最需要现场确认的一个**：从 0.03 起试，确认无撞击/无越限再加大；幅值太小信噪比差、太大会触发限位 |
| 采样/控制率 | **400 Hz** | 论文整机日志 400 Hz；且 PACE 要求"一步仿真 = 一个样本"的等距时间基 | 不要改（两侧仿真都是 `dt=0.0025`） |
| kp / kd | **50 / 1.0** | 低增益；ANYmal 用 85/0.6、Go2W 部署 50/1.0 | 若低频段跟不上，可略升；**一旦定了就不要再改**（要与部署一致） |
| 位置保护 | `\|q\| > 1.2 rad` 中止 | — | 按机械余量收紧 |

## 3. 执行步骤

### 3.1 编译与准备
```bash
cd /home/sysu/Desktop/Project/Bruce/EasyDogFrame/Bruce/simplify

# 1) 启用示例：编辑 src/app/main.cpp，取消 Example62 的三行注释（并把其它示例保持注释）

cd build && make -j$(nproc) && cd ..

# 3) 确认设备：USB2CAN 在 /dev/ttyACM0；狗已刚性固定、离地、水平
```

### 3.2 采集
```bash
./run.sh        # 即 ./bin/can_motor_app
```
程序会：
1. 打印参数与**前置条件清单**，等回车；
2. 把 12 个腿关节 PD 拉到 `DEFAULT_POSE`（3 s），然后**用实测角作为 chirp 偏置**（记录在案）；
3. 打印偏置值（确认 12 个数字合理，无明显离群）；
4. 开始 chirp：**12 个关节同时**按 `des = 偏置 + 0.06·sin(2π(f0t + (f1−f0)/2T·t²))` 运动，400 Hz，20 s；
5. 结束：回偏置姿态 → 失能；
6. 打印**周期统计**与 CSV 路径。

**期间观察**：是否与夹具/线缆干涉；有无异常响声；电机温度；**位置是否越限**（越限会自动中止）。
**中止**：`Ctrl+C`（软急停）或断电。

### 3.3 导出为 PACE 格式

# → 同目录 chirp_data.pt（time / dof_pos / des_dof_pos，三个 float32 张量）

## 5. 验收判据（**先看这几条再交给拟合**）

| 判据 | 阈值 | 不达标怎么办 |
|---|---|---|
| **有效拍数** | 8000（20 s × 400 Hz）完整 | 补采 |
| **平均周期偏差** | **< 1%**（示例会打印） | 该次作废重采（USB 抖动/掉帧） |
| **最大单拍间隔** | < 3 × 周期（7.5 ms） | 同上 |
| 位置越限 | 无 | 降低幅值 |
| 目标幅值 | 与设定一致、无削顶 | 查限位/PD 增益 |
| 关节是否真在跟 | 实测幅值 ≈ 设定幅值（低频段应几乎一致） | 查 kp 是否太低/机械卡滞 |
| 温度 / 电压 | 记录即可，异常升高则缩短时长 | — |

> ⚠️ **时间基是关键**：PACE 的移植版明确"时间戳必须按仿真速率推进（0.0025 s），不匹配的真实数据会被**拒绝**"。
> 所以 `tool/pace_export_dataset.py` 用**理想等距网格** `arange(N)/400` 写 `time`，并用 CSV 里的 `t_actual_s`
> **校验**实际周期；偏差超限默认报错退出（`--force` 才能强导，且会牺牲 delay/damping 估计精度）。

## 6. 与仿真侧对齐时必须注意的三点

1. **关节顺序**：PACE 的 `joint_order` 是 `LF_HAA, LF_HFE, LF_KFE, RF_…, LH_…, RH_…`（**按腿分组**）；
   本框架 CAN 序是 `FL/FR/RL/RR × hip/thigh/calf`（**也按腿分组**）⇒ **一一对应，无需重排**
   （FL↔LF、FR↔RF、RL↔LH、RR↔RH）。CSV 表头已用 PACE 命名，导出脚本按名字取列。
2. **两侧时间的网格约定不同（已知台架差异）**：官方 `data_collection.py` 用 `linspace(0,T,N)`
   （间距 `T/(N-1)`），mjlab 移植版用 `arange(N)*dt`（严格等距）。我们的真机导出用**严格等距**
   ——与移植版一致；若最终要喂**官方** `fit.py`，需注意这一点（我们已决定不补丁官方代码）。
3. **每个关节的偏置/幅值/方向**：官方生成数据时有 `trajectory_bias / directions / scale`（`data_collection.py:117`）。
   本示例：偏置 = 实测 `DEFAULT_POSE` 角、方向 = +1、幅值统一。若要严格对齐官方配置，需要读官方
   ANYmal cfg 里这三项的具体取值并同步（**待办**）。

## 7. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 起立/PD 拉不到 `DEFAULT_POSE` | 夹具夹得太死或线缆受限；确认能自由摆动 |
| 某个关节幅值明显小于其它 | 该关节机械卡滞 or kp 相对负载太低（记录该关节，拟合时重点看其残差） |
| 周期偏差 >1% | USB2CAN 丢帧。检查线缆/供电；重采 |
| 采集结束打印"有越限中止" | 幅值太大或偏置不合理（例如偏置已经把关节推到限位附近）→ 降低幅值/换偏置 |
| 想采多组数据 | 改 `AMP_RAD`/`F1_HZ` 各采一次，分别导出；PACE 官方也是一次一段 |

## 8. 安全（务必遵守）

- 刚性固定后**先手动慢推**机身确认夹具牢靠；**人不要站在腿的摆动平面内**。
- `Ctrl+C` 是软急停（本示例已装 `SIGINT`），但**不等于断电**；异常立即断电。
- 首次试跑建议把 `AMP_RAD` 降到 **0.03**、`DURATION_S` 降到 **5 s**，确认动作与固定都正常后再上正式参数。
- 轮子不参与本测试，但要确认**轮子离地**（否则会顶地）。
