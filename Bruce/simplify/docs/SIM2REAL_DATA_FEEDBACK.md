# 真机数据 → 仿真训练：缩小 sim2real gap 的记录与回馈方案

> 2026-09-29。回答的问题：**"gap 很大时，真机端应该记录哪些数据、怎么回馈给仿真训练？"**
> 与 `docs/CONTACT_PHASE_SIM2REAL.md`（§5 是 gap 分类与主流手段，§7 是落地路线）配套；
> 本文只管**数据侧**：录什么、怎么录、怎么消费。
> 标注：**【现状】** = 本仓库已具备（附文件/示例）；**【缺口】** = 需要新增；**【推断】** = 工程判断。

---

## 0. 一句话结论

**数据本身不会进训练，进训练的是仿真里的「状态转移 `p(s'|s,a)`」和「观测模型」。**
所以录音要围绕**唯一能让这两者变准的最小充分集**：

```
① 我命令了什么   (action / 目标 / kp / kd / τ_ff)   —— 高频，与仿真里施加的 action 一一对应
② 实际发生了什么 (q, q̇, τ, IMU)                     —— 高频，同一时间基准
③ 环境与工况     (负载、地面、电压、延迟设置、权重版本) —— 低频，写 meta
```
**只有 ① 和 ② 且共用一个单调时钟，才能把"控制延迟"与"执行器动态"分离** —— 这是全部辨识的前提。

**优先级（按 ROI，也按"能否立刻验证"）**：

| 顺序 | 做什么 | 为什么 | 已有资产 |
|---|---|---|---|
| **P0** | 把**下发指令**录下来（`send_*.csv` 默认是**关**的）+ **共基准时间戳** | 没有它，任何"仿真 vs 真机"对比都缺少输入侧，无法拟合 | `LogFileSwitch::SEND=false` → 改为 true |
| **P0** | **端到端延迟**辨识（脉冲/阶跃，记录指令与反馈的时间戳） | 最便宜、收益最大；已实测 ≈24 ms，但没进训练 | Example38（需补"指令时间戳落盘"） |
| **P0** | **轮速环**建模（真机是固件速度环 `Dt=50 µs`，sim2sim 是 `kd·(w−q̇)`） | **本项目最大的结构性 gap**，不是参数级 | Example49（kvp 阶跃，需扩展为扫频 + 记指令） |
| **P1** | 执行器辨识：关节 **chirp** + **准静态扫角** + 电池电压 | 力矩常数/摩擦/重力项，直接影响"抬不起腿/下塌" | Example47（chirp）、**Example59**（新，重力/质量）、Example54（摩擦） |
| **P1** | 力矩通道校验（先做） | 用错数据拟合比不拟合更糟 | **Example58**（新） |
| **P2** | 多地面/多负载的**同一轨迹** | 只为**定 DR 区间**（离散度），不是拟合 | 现无 |
| **P3** | 真机在线微调 / 历史隐变量自适应 | 成本高、需重训基建 | 现无 |

## 1. 先分诊：gap 大在哪一类？（不同病因要录不同的数据）

> ### 📋 本次分诊结论（2026-09-29，用户反馈）
> **症状**：① 现象很杂、说不清主因；② **关节跟踪有固定方向偏差 / 抬腿无力 / 整体下塌**。
>
> **含义与行动**：
> 1. ② 是**明确的"执行器+重力项"类症状**，而这一类会**污染所有其它诊断** —— τ 通道有偏、重力项没扣、
>    摩擦没标定时，"抖动/发散/轮子异常"都会被误判成延迟或动力学问题。**所以先修执行器链路，再谈别的。**
> 2. 因为 ① 说明主因不明，**采集要走"全量 P0"而不是挑一项**（见 §7 的 1~5 步）。
> 3. ⚠️ **在录任何数据之前，先排掉两个 0 成本的已知嫌疑**：
>    - **`JOINT_IMPEDANCE[..][THIGH].tau_ff` 的符号冲突**：代码是 **`+5.0f`**，而行内注释与 commit `6546688`
>      的提交信息都写 **`-5`**（且该提交信息说"thigh/calf 置 0"，实际却把 calf 恢复成 12/20）。
>      **符号错的腿重力前馈 = 直接表现为"抬腿无力 / 整体下塌"** —— 这与本次症状②高度吻合。
>      判定方法：真机站立（`Example32` 或 Ex36 起立后静置），把 thigh 的 `tau_ff` 在 `+5 / 0 / −5` 之间切换，
>      对比**腿的下塌量与稳态位置误差**；谁让误差变小谁是对的（10 分钟，1 行改动）。
>    - **零位/方向链**：`Example57`（单腿零位对照，验证 `CONV_A/B`）+ `Example58` 的"零偏"列。
>      症状②里的"固定方向偏差"如果是**常值**而非随负载变化，多半是标定零偏，不是动力学。

**先别急着录一大堆数据**。gap 的症状基本能定位到类别，录错东西等于白录：

| 症状（真机表现） | 最可能的 gap | 需要录的关键数据 | 现有示例 |
|---|---|---|---|
| 站立/慢速就抖、越走越发散；增益稍高就振荡 | **时序延迟 + 执行器相位滞后** | 单步脉冲/阶跃响应（指令与反馈的**时间戳对齐**） | Ex38（缺时间戳落盘） |
| 关节跟踪有**固定方向偏差**；抬腿无力、整体下塌 | **执行器力矩标定/摩擦/重力项** | 准静态多角度 (θ, τ)；chirp (q, q̇, τ, 指令) | Ex47、Ex54、**Ex59** |
| 轮子溜车、疯转、"指令 0 速却在动" | **轮速环建模差异**（固件 SPEED vs 仿真 kd） | 轮速指令→实际轮速的阶跃/扫频；轮空载摩擦基线 | Ex49（扩展）、**Ex58** |
| 平地勉强、上台阶/软地/打滑就废 | **接触/摩擦/地形** | 轮速残差(打滑)、IMU、关节 τ 的接触事件；多地面同轨迹 | 无（见 §7） |
| 只有某个速度/某条命令范围才崩 | **相位与观测分布**（训练分布没覆盖） | 完整策略输入→输出对（obs/action）+ 时间戳 | `rl_*.csv`（**已开**） |
| 动作幅度整体偏小/偏大 | **动作标定/量程** | `sendcan_*.csv`（原始帧）+ `recv_*.csv`（raw 与 cal 都有） | 开关默认关 |

### 1.1 "固定方向偏差"归因：三处常数项交叉验证

"关节有固定方向偏差"有三种完全不同的病因，而**三个已有/新增示例各自会吐出一个"常数项"**，
把它们交叉对比就能定位（这是最省事的判据）：

| 来源 | 常数项 | 含义 | 若它显著非零 |
|---|---|---|---|
| **Example58**（力矩通道） | `零偏` = `kp=kd=0, τ_ff=0` 时的回读 τ | τ 通道的**零点误差** | 硬件/标定问题：查量程寄存器、线束、`ApplyMotorCalibrationTorque` |
| **Example59**（重力矩拟合） | `c`（`τ = a·sinθ + b·cosθ + c` 的常数项） | 准静态下的**恒定偏置**（含 τ 零偏 + 常值摩擦 + 线缆/预载） | 与 Ex58 的零偏对照：两者接近 ⇒ 就是通道零偏；差很多 ⇒ 有额外的机械预载 |
| **Example47**（chirp 最小二乘） | `b`（`τ = Jθ̈ + Bθ̇ + f_c·sign + K_g·θ + b` 的常数项） | 动态拟合出的**常值偏置** | 与上面两者对照；三者一致才说明"偏置是干净的常数"，可以用 `tau_ff` 直接抵掉 |

**判据**：
- 三者**同号同量级** ⇒ 纯零偏 → 在 `tau_ff` 表里直接补偿（1 行改动）。
- `Ex59.c` 明显大于 `Ex58.零偏` ⇒ 有机械预载/常值摩擦 → 需要方向相关的补偿，不能只加常数。
- `Ex47.K_g`（线性化重力刚度）与 `Ex59.G_j`（真实重力矩幅值）**量级对不上** ⇒ 说明重力项在工作点附近变化剧烈，
  必须用 `sinθ` 形式而不是 `K_g·θ`，否则一旦偏离工作点就"下塌/抬腿无力"。

> 👉 **把你的具体症状告诉我，我可以把范围缩到 1~2 类**，避免全量采集。

## 3. 六组"主动激励"协议（数据要有覆盖性，光录正常行走没用）

> 回馈训练的价值取决于激励**是否覆盖了模型需要辨识的频段与工况**。
> 下面每组都标了"复用什么、缺什么"。

### A. 单关节位置 chirp（→ 执行器动力学 `I_a, d, τ_f, q̃_b, T_d`）
- **已有**：Example47（悬空 chirp，`log/sysid_all.csv` 出 J/B/f_c/K_g/b）。
- **缺**：① 同时记录**下发指令**；② 采样率提到 ≥1 kHz 或至少保证 500 Hz 无丢帧；③ 激励频段按 **0.1–2.0 Hz 位置 chirp**（Bjelonic IJRR 2026 的做法：上限取 `f_policy/2`；若结构限制达不到，至少覆盖控制器运动最高频的 2 倍）。
- **为什么值得重做**：Bjelonic 只用 **~20 s 空中数据** + CMA-ES 就同时辨识出 5 类参数并拿到 **CoT −32%**，性价比是所有手段里最高的。本项目的 Ex47 是**离线最小二乘**（对噪声/偏置更敏感），可考虑改为"并行仿真回放 + CMA-ES"。

### B. 准静态扫角（→ 重力项 `G_j = m·g·d` 与质量-质心）
- **已有**：**Example59**（新增，单关节双向慢扫 14 点 + 对 `[sinθ, cosθ, 1]` 三参数最小二乘）。
- **配套**：台秤称重（机身/大腿组件/小腿+轮组件）。
- **用途**：填 `LINK_DYNAMICS`/`BODY_MASS`；也是"扣掉自重再算接触力"的前提。

### C. 单步脉冲 / 阶跃（→ 端到端纯延迟 `T_d`）
- **已有**：Example38（正弦扫频测 Action Delay，相位法）。
- **缺**：记录**指令时间戳**（否则只能得到"总相位滞后"，分不出纯延迟与执行器滞后）。
- **做法**：发一个只持续 1 个控制步的阶跃，测"指令写入时刻 → 编码器首次变化"的时间差；分别在 **PD 环（500 Hz）** 与 **策略环（50 Hz）** 各测一次。
- **参考量级**：MCU PD 环 ~3 ms、板载策略环 15–19 ms、本项目实测端到端 ≈24 ms（18–30 ms）、Bjelonic 拟合出的全局 `T_d = 7.5 ms`。

### D. 轮速环扫频/阶跃（→ **本项目最大的结构性 gap**）
- **已有**：Example49（悬空单轮 SPEED 环 kvp 扫描）。
- **缺**：把"轮速指令 → 实际轮速"当成一个**待辨识的伺服模型**来测：给 `ω_des` 做阶跃（0→1→2→5 rad/s）与 chirp（0.1→20 Hz），500 Hz 记 `ω_des`、`ω_meas`（**raw 与滤波后都要**）、`τ_w`。
- **为什么关键**：真机轮子是固件速度环（**手册明确 `Dt = 50 µs`，即 20 kHz 内环**），而 sim2sim 里是 `kd·(w_target − qd)`（`WHEEL_KD=2.0`）。**这是模型结构不同，不是参数不同** —— 无论怎么调 DR 都补不上。正确做法是在仿真里把轮子建成**速度伺服**（Wheel-Legged-Gym/CTBC/Go2-W 的共识：动作 = 速度目标 + 仿真用 `stiffness=0, damping=k` 的 PD 近似），再用这组数据拟合 `k`、饱和、死区、延迟。

### E. 落地冲击与负载转移（→ 接触刚度/阻尼、法向力）
- 悬空 → 人工缓慢放到地面 → 单腿离地/恢复 → 站立时施加侧向推力。
- 记 500 Hz 的 `q/q̇/τ` + 100 Hz IMU。
- 用途：接触参数（`solref/solimp`、`bounce_threshold_velocity`）与"接触检测阈值"的标定数据；也是 Ex58/59 之后的 v1 指示器的验证集。

### F. 多地面 / 多负载的**同一条**轨迹（→ **定 DR 区间**，不是拟合）
- 同一条 30 s 轨迹（直行 + 转向 + 一次抬腿）在 **水泥 / 瓷砖 / 地毯 / 草地 / 斜坡** 上各跑一遍，负载 0 / +2 / +5 kg 各一遍。
- **消费方式不同**：不用于拟合参数，而是统计**离散度**（摩擦、Kp/Kd 等效偏差、延迟 σ），用这个离散度去**设 DR 上下界** —— 这是 Rudin 2021 "少而准 DR"的做法：只随机化**地面摩擦 + 观测噪声（按真机实测标定）+ 随机推力**三项，而不是全域乱随。

## 4. 数据怎么"回馈"到仿真训练：四条消费路径

### 路径 1：参数辨识 → 直接改仿真模型（最快见效，不需重训策略）
把 §3 的产物写成仿真的**物理/执行器参数**：
- 关节：`frictionloss`（库仑）、`damping`（粘性）、`armature`（转子折算惯量）—— 参照 Barkour `damping=0.024, frictionloss=0.13, armature=0.011`；MuJoCo Menagerie Go2 `damping=2, armature=0.01, frictionloss=0.2`
- 执行器：DC 电机四象限曲线 `τ_max(q̇) = clip(τ_stall·(1 − q̇/q̇_max), −∞, τ_con)`（Isaac Lab `DCMotor`），并加总功率上限 `|τ|ᵀ|q̇| ≤ P_max`
- 延迟：`action_delay_steps`（本项目实测 ≈24 ms ⇒ ≥1 步）
- 轮子：**换成速度伺服模型**（见 D）
- 电压：把 Vbus 作为力矩上限的缩放因子（Tan 2018 用 `V_pwm = V·(kp·e + kd·ė)`）

### 路径 2：离散度 → 定 DR 区间（改分布，不强调参）
用 §3-F 的统计量设随机化范围，而不是拍脑袋。可作为起点抄的区间：
```
摩擦           [0.3, 1.25]（以真机实测为准；轮足项目用 [0.1,2.0] / [0.05,1.5]）
质量/payload    ±(1~5) kg ；CoM ±5 cm
Kp/Kd 因子      [0.8, 1.3] / [0.5, 1.5]
电机强度        [0.9, 1.1]（或 [0.8,1.2]）
动作延迟        [0, 2] 步 @50 Hz（或连续 [0,15] ms，观测历史插值）
编码器/零位偏置 ±0.015 rad（系统性偏置，白噪声覆盖不了）
观测噪声        q ±0.01 rad、q̇ ±1.5 rad/s、gyro ±0.2 rad/s、gravity ±0.05
```
⚠️ DR 有代价：**均值回报更低、方差更小**（"随机化不是免费午餐"）。所以走"**少而准**"：只随那些**有实测依据**的项。

### 路径 3：轨迹回放拟合（把真机数据直接变成仿真参数）——**推荐作为主力**
```
真机：同一段 30~60 s，500 Hz 记 (指令, q, q̇, τ)
  ↓
仿真：新增 sim2sim 的 --replay <csv> 模式：不跑策略，直接喂记录的指令，输出同格式 (q, q̇, τ)
  ↓
拟合：min_p Σ‖q_real − q_sim(p)‖² + λ·Σ‖τ_real − τ_sim(p)‖²
      p = [I_a, d, τ_f, q̃_b, T_d, 轮速环参数...]，用 CMA-ES（比贝叶斯优化稳）+ 4096 并行环境
  ↓
产出：可直接写进仿真模型的参数 + 残差曲线（残差大的频段就是下一个要查的 gap）
```
**为什么推荐**：它同时覆盖"参数 + 延迟 + 轮速环"，且**残差谱本身就是分诊工具**（残差集中在低频 → 重力/摩擦；集中在高频/相位 → 延迟/惯量）。
**已有基础**：`dogurdf_sim2sim_deploy/src/sim2sim.py`（已有 `--record/--watch_dir/--real_actuator/--wheel_gate`）、`tool/verify_friction_ff.py`（MuJoCo 里做拟合的先例）、`tool/friction_id_offline.py`（离线回归）。缺的是 `--replay` 与 `tool/replay_fit.py`。

### 路径 4：真机数据直接进训练（最后做）
- **行为克隆/离线 RL 微调**：把真机轨迹当 offline dataset（Smith 2022 用 REDQ + 自动 reset，草坪 <2 h 收敛）—— 需要**自动 reset + 板载奖励估计 + 安全约束**，否则别做。
- **历史隐变量自适应（HIM / DreamWaQ 式）**：**与我们的传感器配置完全一致**（纯关节+IMU），但要先有"仿真 + 真机配对数据"与重训基建；且它治的是**感知误差**，治不了执行器/延迟误差。**顺序上应该在路径 1~3 之后**。

## 6. 工程约束（不做这些，录到的数据会骗你）

1. **落盘不得干扰实时环**。已有一条历史教训：`SENDCAN` 高频写入曾与 `LogRecv` 争 `MotorLogger` 的锁，是"接收线程卡死"的嫌疑源（`include/common/motor_logger.h` 注释）。所以 500 Hz 全量落盘要：**独立写线程 + 无锁环形缓冲 + 批量 flush**，而不是在收发线程里 `fprintf`。
2. **共用单调时钟**，并在每条记录里带上"该帧的产生时刻"与"落盘时刻"两个时间戳（区分采集延迟与真实延迟）。
3. **raw 与 cal 都要留**（现在有，别丢）：`raw` 用于发现编码/量程问题，`cal` 用于模型拟合。
4. **区分"滤波后观测"与"真实量"**：轮速有上位机一阶低通 α=0.2（τ≈10 ms）、`WHEEL_CMD_ALPHA` 又对目标做了低通。拟合执行器动力学时必须用**未滤波**的原始轮速，否则会把低通误辨成执行器滞后。
5. **电压/温度漂移**：长录制要分段，并在 meta 记起止 Vbus/温度；否则"参数漂移"会被误当成"噪声"。
6. **数据量与覆盖的权衡**：回放拟合只需 **20~60 s** 高覆盖数据；DR 区间统计需要**多地面 × 多负载**各 10~30 s。500 Hz、16 关节 ×3 量 ≈ **150~200 KB/s**（10 分钟 ≈ 100 MB），完全可接受。
7. **先跑 Example58**：力矩通道不可信时，用 τ 拟合出的任何参数都是错的 —— 这是本轮新增的"前提件"。

## 8. 未决 / 风险

1. **本方案未基于实际数据**：§1 的分诊表是"症状→病因"的通用映射，不是对你机器人的诊断。**给我症状（或一段 `log/rl_*.csv` + `log/recv_*.csv`），我可以把范围缩到 1~2 类并给出具体阈值。**
2. **轮速环在仿真里怎么建**，需要先决定：是把轮子建成速度伺服（主流、推荐），还是把真机轮子改成力矩控制（若固件支持）—— 前者改仿真、后者改真机，两者不可混。
3. ~~`send_*.csv` 打开后是否会拖慢 500 Hz 环~~ → **已用 S2RDataset 的无锁环形缓冲 + 独立写线程规避**（生产者只做一次 ~0.6 KB 拷贝，队列满则丢弃并计数）。⚠ 仍建议首次录制时做一次压力测试：跑 5 min 后看 `dropped` 是否为 0（`Finish()` 会打印），且 `/tmp/test_dataset` 的自测已验证 3000 行 0 丢弃。
4. **Vbus/温度读取**占用 CAN 带宽：现实现为 1 Hz 轮询 4 个（Vbus）+ 16 个（温度）= 20 帧/s，相对稳态 8000 帧/s（16 电机 × 500 Hz）约 0.4% —— 已按此实现；若发现 `motor_send` 周期抖动，把温度也降到 4 个/路。
5. **真机微调（路径 4）暂不建议**：缺自动 reset 与板载奖励估计，风险高于收益。
